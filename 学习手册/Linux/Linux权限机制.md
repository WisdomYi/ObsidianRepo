
Linux的权限限制机制是保障系统安全的核心，从基础的文件权限到复杂的隔离技术，形成了多层防护网。而root用户创建的Docker容器无法停止，往往与Docker自身的**权限隔离设计**和**命名空间机制**有关，并非单纯的root权限问题。 Linux的权限控制机制从简单到复杂，覆盖了不同场景的安全需求，以下是核心机制的详细解析： 

| 机制名称                   | 核心原理                                              | 应用场景                            | 特点                                      |     |
| ---------------------- | ------------------------------------------------- | ------------------------------- | --------------------------------------- | --- |
| **UGO权限模型**            | 基于用户（User）、组（Group）、其他用户（Other）的读（r）、写（w）、执行（x）权限 | 基础文件/目录权限控制                     | 简单直观，每个文件对应3组权限（3位一组，共9位）               |     |
| **ACL（访问控制列表）**        | 对UGO的扩展，可对特定用户/组设置精细化权限                           | 需要给多个用户/组分配不同权限的场景（如共享目录）       | 支持更灵活的权限分配，用`getfacl`/`setfacl`管理       |     |
| **SUID/GID**           | 执行文件时临时获取文件所有者/所属组的权限                             | 允许普通用户执行需要高权限的命令（如`passwd`修改密码） | 权限提升有严格限制，仅对可执行文件有效                     |     |
| **sudo**               | 临时赋予普通用户root权限（需配置`/etc/sudoers`）                 | 避免直接使用root登录，控制用户可执行的高权限命令      | 可记录操作日志，细粒度限制用户权限范围                     |     |
| **SELinux**            | 基于安全上下文（用户、角色、类型）的强制访问控制（MAC）                     | 高安全性场景（如服务器、嵌入式系统）              | 规则复杂，默认关闭，违反规则的操作会被拒绝（需通过`audit.log`排查） |     |
| **AppArmor**           | 基于路径的强制访问控制，为进程定义允许的操作范围                          | 简化版MAC，常见于Ubuntu等发行版            | 配置文件更易理解，按进程限制权限（如限制nginx只能访问特定目录）      |     |
| **Linux capabilities** | 将root权限拆分为细粒度的能力（如`CAP_NET_RAW`允许使用原始套接字）         | 减少进程的冗余权限（如Docker容器仅保留必要能力）     | 避免进程获取完整root权限，降低安全风险                   |     |
| **命名空间（Namespaces）**   | 对进程隔离PID、网络、挂载点等资源，使进程仅能看到自己的"隔离环境"               | 容器技术（Docker、LXC）、虚拟化场景          | 核心隔离技术，让进程误以为自己是"独立系统"                  |     |
| **cgroups（控制组）**       | 限制进程对CPU、内存、IO等资源的使用                              | 资源配额管理（如限制容器的最大内存）              | 不直接控制权限，而是控制资源使用上限                      |     |
